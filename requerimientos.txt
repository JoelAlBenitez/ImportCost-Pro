Objetivo general
Construir una aplicación ASP.NET Core MVC + Entity Framework Core, usando .NET
9, para que una empresa importadora pueda registrar órdenes de importación con
múltiples productos y calcular el costo real final de importación de cada producto,
tomando en cuenta valor FOB, flete internacional, seguro, tasa de cambio,
aranceles, ITBIS, gastos locales, gastos portuarios, transporte local y márgenes de
ganancia.
El sistema debe permitir calcular el landed cost, es decir, el costo total de un
producto una vez puesto en almacén local.

Mantenimiento de Países
Al ingresar a la opción Países desde el menú principal de la aplicación, el sistema
debe enviar al usuario al mantenimiento de países.
Este mantenimiento permitirá registrar, consultar, editar y eliminar los países que
serán utilizados en otros módulos del sistema, como proveedores, importadores,
productos y órdenes de importación.
Pantalla inicial del mantenimiento
En la pantalla inicial del mantenimiento de países, el sistema debe mostrar un
listado con todos los países registrados.
De cada país se debe mostrar la siguiente información:
Campo Descripción
Nombre del país Nombre completo del país registrado. Ejemplo: República
Dominicana, Estados Unidos, China.
Código ISO Código internacional corto que identifica al país. Ejemplo: DO,
US, CN.
Estado Indica si el país está activo o inactivo dentro del sistema.
Cada país listado debe tener las siguientes acciones:
● Editar: permite modificar los datos del país.
● Eliminar: permite eliminar el país, siempre que no esté relacionado con otros
registros del sistema.
Arriba del listado debe existir un botón con el texto Crear país.

Validaciones para crear país
El formulario de creación debe cumplir las siguientes validaciones:
● El nombre del país es requerido.
● El código ISO es requerido.
● El código ISO debe tener entre 2 y 3 caracteres.
● El código ISO no puede repetirse.
● El estado es requerido.
● No se debe permitir crear dos países con el mismo código ISO.
● El código ISO debe guardarse preferiblemente en mayúscula.
Ejemplo:
Si el usuario escribe "do", el sistema puede guardar "DO".
Si el usuario intenta registrar un país con un código ISO ya existente, el sistema
debe mostrar un mensaje como:
“Ya existe un país registrado con este código ISO.”
Al final del formulario de creación debe haber dos botones:
● Volver atrás: devuelve al usuario al listado de países sin guardar cambios.
● Crear país: guarda el país en el sistema.
Al hacer clic en Crear país, si los datos son válidos, el sistema debe registrar el país
y redirigir al usuario a la pantalla inicial del mantenimiento de países.

● Cancelar
● Aceptar

Si el usuario pulsa Aceptar, el sistema debe intentar eliminar el país.

● Un importador.

Representa el país desde donde normalmente se importa el producto.
Este campo no debe escribirse manualmente. Debe seleccionarse desde un select
cargado con los países activos registrados en el mantenimiento de países.
Ejemplo:
● China
● Estados Unidos
● México
● España
Este país funciona como valor predeterminado. Si en una orden específica el
producto viene desde otro país, se usará el país configurado en la orden de
importación para esa importación.
Categoría arancelaria
Representa la clasificación arancelaria del producto.
Esta categoría será utilizada para determinar:
● Porcentaje de arancel.
● Si aplica ITBIS.
● Si aplica impuesto selectivo.
● Porcentaje de impuesto selectivo, si aplica.
Este campo no debe escribirse manualmente. Debe seleccionarse desde un select
cargado con las categorías arancelarias activas registradas en el mantenimiento de
categorías arancelarias.
Peso unitario
Representa el peso de una unidad del producto.
Debe expresarse en kilogramos.
Ejemplo:
● 2.50
● 0.75
● 10.00
Este campo será utilizado para distribuir gastos por peso cuando un gasto de
importación tenga como método de distribución por peso.
Largo, ancho y alto
Representan las dimensiones físicas de una unidad del producto.
Deben expresarse en centímetros.
Ejemplo:
● Largo: 40
● Ancho: 30
● Alto: 10
Estos campos serán utilizados para calcular el volumen total del producto cuando
un gasto de importación tenga como método de distribución por volumen.
El volumen unitario se calcula de la siguiente manera:
VolumenUnitario = Largo * Ancho * Alto
El volumen total dentro de una orden se calcula así:
VolumenTotalProducto = Cantidad * Largo * Ancho * Alto
Nota: estos campos no calculan por sí solos el peso volumétrico. El peso
volumétrico requiere un factor volumétrico y puede ser utilizado en otros módulos si
se define esa regla.
Unidad de medida
Representa la unidad comercial en la que se maneja el producto.
Valores:
● Unidad
● Caja
● Paquete
● Docena
● Galón
● Metro
Este campo debe manejarse como un select con valores predefinidos.
Descripción
Permite registrar información adicional del producto.
Ejemplo:
Laptop empresarial de 14 pulgadas con procesador Intel.
Producto importado para venta al detalle.
Este campo es opcional.
Estado
Indica si el producto está activo o inactivo.
● Si el producto está activo, puede aparecer en los selects para agregar
productos a nuevas órdenes de importación.
● Si el producto está inactivo, no debe aparecer como opción para nuevas
órdenes.
● Si un producto inactivo ya fue usado en una orden anterior, debe seguir
mostrándose en esa orden histórica.

● Cancelar
● Aceptar

● No se debe permitir eliminar productos que estén asociados a órdenes de

● Si un producto está asociado a órdenes de importación, no se deben permitir
cambios en campos críticos que afecten trazabilidad o cálculos históricos.

aplicación, el sistema debe enviar al usuario al mantenimiento de categorías

determinar los impuestos aplicables durante el cálculo del landed cost.
Una categoría arancelaria representa una clasificación fiscal o aduanal asociada a un
producto. Esta clasificación permite definir el porcentaje de arancel, si el producto
aplica ITBIS y si aplica impuesto selectivo al consumo.

Restricciones importantes al editar

● Importador.
● Proveedor.
● País de origen.
● Moneda.
● Fecha de la orden.
● Modalidad de transporte.
Esto evita que el cálculo oficial quede inconsistente con los datos base usados
originalmente.
Sí se puede permitir modificar datos no críticos como:
● Número de orden, siempre que no se repita y siempre que la orden no esté
cerrada.
● Estado, únicamente mediante acciones controladas del sistema.
El estado no debe cambiarse libremente desde cualquier valor hacia cualquier otro.
Los cambios de estado deben seguir reglas controladas.

Abierta -> Calculada
Calculada -> Cerrada
Abierta -> Cancelada
No se debe permitir:
Cerrada -> Abierta
Cancelada -> Abierta
Cerrada -> Calculada
Cancelada -> Calculada
Si el usuario intenta editar una orden cerrada o cancelada, el sistema debe mostrar

Si el usuario intenta modificar campos críticos de una orden ya calculada, el sistema

Cálculos del detalle de productos
FOB total del producto
El FOB total del producto se calcula de la siguiente manera:
FOBProducto = Cantidad * PrecioUnitarioFOB
Ejemplo:
● Cantidad = 10
● PrecioUnitarioFOB = 500
● FOBProducto = 10 * 500 = 5,000
El resultado está expresado en la moneda de la orden.
FOB total de la orden
El FOB total de la orden se calcula sumando el FOB de todos los productos
agregados:
FOBTotalOrden = Σ FOBProducto
Este valor debe mostrarse en el resumen FOB del detalle de la orden.
Peso total del producto
El peso total del producto se calcula de la siguiente manera:
PesoTotalProducto = Cantidad * PesoUnitario
Ejemplo:
● Cantidad = 10
● PesoUnitario = 2.50 kg
● PesoTotalProducto = 10 * 2.50 = 25 kg
Este valor será usado cuando un gasto de importación se distribuya por peso.
Peso total de la orden
El peso total de la orden se calcula sumando el peso total de todos los productos
agregados:
PesoTotalOrden = Σ PesoTotalProducto
Volumen total del producto
El volumen total del producto se calcula usando las dimensiones registradas en el
mantenimiento de productos:
VolumenTotalProducto = Cantidad * Largo * Ancho * Alto
Las dimensiones deben estar expresadas en centímetros.
Ejemplo:
● Cantidad = 10
● Largo = 40 cm
● Ancho = 30 cm
● Alto = 10 cm
VolumenTotalProducto = 10 * 40 * 30 * 10 = 120,000 cm³
Este valor será usado cuando un gasto de importación se distribuya por volumen.
Si el producto no tiene largo, ancho y alto configurados, el sistema puede mostrar el
volumen como No disponible.
Sin embargo, si existe algún gasto configurado para distribuirse por volumen,
entonces todos los productos de la orden deben tener dimensiones válidas antes de
calcular el landed cost.
Volumen total de la orden
El volumen total de la orden se calcula sumando el volumen total de todos los
productos agregados que tengan dimensiones válidas:
VolumenTotalOrden = Σ VolumenTotalProducto
Si la orden tiene gastos distribuidos por volumen y uno o más productos no tienen
dimensiones configuradas, no se debe permitir calcular el landed cost.

Conversión de gastos a moneda local
Si el gasto está registrado en la moneda local, no se necesita conversión y se debe
usar:
TasaCambio = 1
Si el gasto está registrado en una moneda diferente a la moneda local, el sistema
debe buscar una tasa de cambio activa con:
MonedaOrigen = MonedaGasto
MonedaDestino = MonedaLocal
FechaVigencia <= FechaGasto
De las tasas que cumplan esas condiciones, el sistema debe usar la tasa con la
fecha de vigencia más reciente.
La conversión se realiza así:
MontoGastoLocal = MontoGasto * TasaCambio
Si no existe una tasa válida, no se debe permitir calcular el landed cost. Para evitar
errores posteriores, el sistema también debe advertirlo al registrar o editar el gasto.
Uso de los gastos en el cálculo
Los gastos de tipo Flete internacional y Seguro internacional se utilizan para
calcular el CIF del producto.
CIFProducto = FOBProductoLocal + FleteAsignadoProducto +
SeguroAsignadoProducto
Los demás tipos de gasto se consideran gastos locales asignados al producto:
GastosLocalesProducto = Σ GastosLocalesAsignadosAlProducto
El costo total importado del producto se calcula sumando:
CostoTotalImportadoProducto = FOBProductoLocal +
FleteAsignadoProducto + SeguroAsignadoProducto + ArancelProducto +
ImpuestoSelectivoProducto + TasaServicioAduanalProducto +
ITBISProducto + GastosLocalesProducto

Cálculo de Landed Cost
Al ingresar a la opción Cálculo de landed cost desde el menú principal de la
aplicación, el sistema debe mostrar una pantalla que permita seleccionar una orden
de importación y calcular el costo total importado de cada producto agregado a
dicha orden.
Este módulo se encarga de calcular el landed cost, es decir, el costo real final de
cada producto una vez considerada la mercancía, flete, seguro, aranceles,
impuestos, tasas aduanales y gastos locales.
El cálculo debe realizarse usando los datos registrados en:
● Orden de importación.
● Productos agregados a la orden.
● Gastos de importación.
● Monedas.
● Tasas de cambio.
● Categorías arancelarias.
● Configuración de impuestos.
El resultado del cálculo debe mostrarse en pantalla y el sistema debe permitir
guardarlo como cálculo oficial de la orden.
El texto original del módulo indica que el cálculo incluye validaciones, conversión a
moneda local, prorrateo de flete/seguro, cálculo de CIF, arancel, impuesto selectivo,
tasa de servicio, ITBIS, gastos locales y precio sugerido.
Pantalla inicial del cálculo
En la pantalla de Cálculo de landed cost, el sistema debe mostrar un formulario
con un campo tipo select para seleccionar una orden de importación.
El select debe mostrar únicamente órdenes en estado:
● Abierta
No deben mostrarse órdenes en estado:
● Calculada.
● Cerrada.
● Cancelada.
Por defecto, el select debe venir con la orden abierta más reciente seleccionada.
Debajo del select debe haber un botón con el texto: “Calcular landed cost”
Validaciones previas al cálculo
Al hacer clic en Calcular landed cost, el sistema debe validar la orden seleccionada
antes de realizar cualquier cálculo.
La orden debe cumplir las siguientes condiciones:
● La orden debe existir.
● La orden debe estar en estado Abierta.
● La orden debe tener al menos un producto agregado.
● La orden debe tener una moneda válida.
● Debe existir una moneda local activa configurada en el mantenimiento de
monedas.
● Si la moneda de la orden es diferente a la moneda local, debe existir una tasa
de cambio activa desde la moneda de la orden hacia la moneda local.
● La tasa de cambio de la orden debe tener fecha de vigencia menor o igual a
la fecha de la orden.
● La orden debe tener un gasto de tipo Flete internacional registrado.
● La orden debe tener un gasto de tipo Seguro internacional registrado.
● Cada gasto registrado debe tener una moneda válida.
● Si un gasto está en una moneda diferente a la moneda local, debe existir una
tasa de cambio activa desde la moneda del gasto hacia la moneda local.
● La tasa de cambio del gasto debe tener fecha de vigencia menor o igual a la
fecha del gasto.
● Cada producto agregado debe tener una categoría arancelaria válida.
● Debe existir una configuración de impuestos registrada.
● Si existen gastos distribuidos por valor FOB, el FOB total de la orden debe
ser mayor que 0.
● Si existen gastos distribuidos por peso, todos los productos deben tener peso
unitario mayor que 0.
● Si existen gastos distribuidos por volumen, todos los productos deben tener
largo, ancho y alto mayores que 0.
● Si existen gastos distribuidos por cantidad, la cantidad total de productos
debe ser mayor que 0.
● El margen de ganancia deseado de cada producto debe ser mayor o igual
que 0 y menor que 100.
Si alguna validación falla, no se debe mostrar el resultado del cálculo y se debe
indicar exactamente cuál es el problema.
Ejemplo:
“No se puede calcular el landed cost porque existen gastos distribuidos
por peso y uno o más productos no tienen peso configurado.”
Otro ejemplo:
“No se puede calcular el landed cost porque la orden está registrada en
USD y no existe una tasa de cambio activa hacia la moneda local para la
fecha de la orden.”
Paso 1: Calcular FOB por producto
Por cada producto agregado a la orden, el sistema debe calcular el FOB del
producto.
FOBProducto = Cantidad * PrecioUnitarioFOB
Ejemplo:
● Cantidad = 10
● PrecioUnitarioFOB = 500
● FOBProducto = 10 * 500 = 5,000
El FOB del producto está expresado en la moneda de la orden.
Luego se debe calcular el FOB total de la orden:
FOBTotalOrden = Σ FOBProducto
Si el FOB total de la orden es 0, no se debe permitir continuar el cálculo.
Paso 2: Convertir FOB a moneda local
El sistema debe identificar la moneda local activa configurada en el mantenimiento
de monedas.
Si la moneda de la orden es igual a la moneda local, se debe usar:
TasaCambioOrden = 1
Si la moneda de la orden es diferente a la moneda local, el sistema debe buscar una
tasa de cambio activa con las siguientes condiciones:
MonedaOrigen = MonedaOrden
MonedaDestino = MonedaLocal
FechaVigencia <= FechaOrden
De las tasas que cumplan esas condiciones, se debe usar la tasa con la fecha de
vigencia más reciente.
Luego se convierte el FOB de cada producto:
FOBProductoLocal = FOBProducto * TasaCambioOrden
Y el FOB total:
FOBTotalLocal = FOBTotalOrden * TasaCambioOrden
Paso 3: Convertir gastos a moneda local
Cada gasto de la orden debe convertirse a moneda local antes de ser prorrateado.
Si la moneda del gasto es igual a la moneda local, se debe usar:
TasaCambioGasto = 1
Si la moneda del gasto es diferente a la moneda local, el sistema debe buscar una
tasa de cambio activa con las siguientes condiciones:
MonedaOrigen = MonedaGasto
MonedaDestino = MonedaLocal
FechaVigencia <= FechaGasto
De las tasas que cumplan esas condiciones, se debe usar la tasa con la fecha de
vigencia más reciente.
Luego se convierte el gasto:
GastoLocal = MontoGasto * TasaCambioGasto
Paso 4: Calcular totales base para distribución
Antes de prorratear gastos, el sistema debe calcular los totales que servirán como
base de distribución.
FOBTotalLocal = Σ FOBProductoLocal
PesoTotalOrden = Σ PesoTotalProducto
VolumenTotalOrden = Σ VolumenTotalProducto
CantidadTotalOrden = Σ CantidadProducto
Donde:
PesoTotalProducto = Cantidad * PesoUnitario
Y:
VolumenTotalProducto = Cantidad * Largo * Ancho * Alto
Si algún método de distribución necesita uno de estos totales y el total
correspondiente es 0, no se debe permitir continuar el cálculo.
Paso 5: Prorratear gastos por producto
Todos los gastos de la orden deben asignarse proporcionalmente a los productos
según el método de distribución configurado en cada gasto.
Si el método de distribución es Por valor FOB:
FactorProducto = FOBProductoLocal / FOBTotalLocal
GastoAsignadoProducto = GastoLocal * FactorProducto
Si el método de distribución es Por peso:
FactorProducto = PesoTotalProducto / PesoTotalOrden
GastoAsignadoProducto = GastoLocal * FactorProducto
Si el método de distribución es Por volumen:
FactorProducto = VolumenTotalProducto / VolumenTotalOrden
GastoAsignadoProducto = GastoLocal * FactorProducto
Si el método de distribución es Por cantidad:
FactorProducto = CantidadProducto / CantidadTotalOrden
GastoAsignadoProducto = GastoLocal * FactorProducto
El sistema debe calcular por cada producto:
● Flete asignado.
● Seguro asignado.
● Gastos locales asignados.
Paso 6: Separar flete, seguro y gastos locales
Para el cálculo del CIF se deben tomar únicamente los gastos de tipo:
● Flete internacional
● Seguro internacional
El resto de gastos se consideran gastos locales asignados al producto.
El sistema debe identificar por producto:
FleteAsignadoProducto = gasto asignado cuyo tipo es Flete internacional
SeguroAsignadoProducto = gasto asignado cuyo tipo es Seguro internacional
GastosLocalesProducto = Σ gastos asignados cuyo tipo no sea Flete internacional ni
Seguro internacional
Paso 7: Calcular CIF por producto
Una vez asignado el flete y el seguro, se debe calcular el CIF de cada producto.
CIFProducto = FOBProductoLocal + FleteAsignadoProducto +
SeguroAsignadoProducto
El CIF total de la orden será:
CIFTotal = Σ CIFProducto
Paso 8: Calcular arancel
Cada producto tiene una categoría arancelaria asociada.
El porcentaje de arancel se toma desde la categoría arancelaria del producto.
Como el porcentaje se captura como valor visible, por ejemplo 8 para representar
8%, la fórmula debe ser:
ArancelProducto = CIFProducto * (PorcentajeArancel / 100)
Si el porcentaje de arancel es 0, el arancel del producto será 0.
Paso 9: Calcular impuesto selectivo, si aplica
Si la categoría arancelaria del producto indica que aplica impuesto selectivo, se
debe calcular:
ImpuestoSelectivoProducto = CIFProducto * (PorcentajeImpuestoSelectivo / 100)
Si la categoría arancelaria indica que no aplica impuesto selectivo, el impuesto
selectivo del producto debe ser 0.
Paso 10: Calcular tasa de servicio aduanal
La tasa de servicio aduanal se calcula sobre el CIF del producto.
El porcentaje viene desde la configuración de impuestos activa.
Como el porcentaje se captura como valor visible, por ejemplo 0.4 para representar
0.4%, la fórmula debe ser:
TasaServicioAduanalProducto = CIFProducto * (PorcentajeTasaServicioAduanal /
100)
Paso 11: Calcular ITBIS
El ITBIS se calculará únicamente si la categoría arancelaria del producto indica que
aplica ITBIS.
La base del ITBIS será:
BaseITBISProducto = CIFProducto + ArancelProducto +
ImpuestoSelectivoProducto + TasaServicioAduanalProducto
Luego se calcula:
ITBISProducto = BaseITBISProducto * (PorcentajeITBIS / 100)
El porcentaje general de ITBIS viene desde la configuración de impuestos.
Si el producto no aplica ITBIS, el ITBIS será 0.
Paso 12: Calcular costo total importado por producto
El costo total importado de cada producto se calcula de la siguiente manera:
CostoTotalImportadoProducto = FOBProductoLocal + FleteAsignadoProducto +
SeguroAsignadoProducto + ArancelProducto + ImpuestoSelectivoProducto +
TasaServicioAduanalProducto + ITBISProducto + GastosLocalesProducto
Paso 13: Calcular costo unitario importado
El costo unitario importado se calcula dividiendo el costo total importado del
producto entre la cantidad importada.
CostoUnitarioImportado = CostoTotalImportadoProducto / CantidadProducto
Si la cantidad del producto es 0, no se debe permitir calcular el landed cost.
Paso 14: Calcular precio de venta sugerido
El precio de venta sugerido se calcula usando el margen de ganancia deseado
registrado para cada producto en la orden.
El margen de ganancia deseado se captura como porcentaje visible.
Ejemplo:
● 30 = 30%
● 25 = 25%
● 0 = sin margen
La fórmula debe ser:
PrecioVentaSugerido = CostoUnitarioImportado / (1 - (MargenDeseado / 100))
Ejemplo:
● CostoUnitarioImportado = 1,000
● MargenDeseado = 30
● PrecioVentaSugerido = 1,000 / (1 - (30 / 100))
● PrecioVentaSugerido = 1,000 / 0.70
● PrecioVentaSugerido = 1,428.57
Si el margen deseado es 0, el precio de venta sugerido será igual al costo unitario
importado.
No se debe permitir margen igual o mayor que 100, porque provocaría una división
inválida.

Guardar cálculo oficial
Después de mostrar el resultado, el sistema debe permitir guardar el cálculo como
resultado oficial de la orden.
Al guardar el cálculo oficial, el sistema debe:
● Crear un registro de resultado general del cálculo.
● Crear el detalle del cálculo por producto.
● Guardar los totales calculados.
● Guardar la moneda local usada.
● Guardar la tasa de cambio usada para convertir la orden, si aplica.
● Guardar los porcentajes de impuestos usados.
● Guardar los porcentajes de arancel e impuesto selectivo usados por
producto.
● Guardar los gastos asignados por producto.
● Cambiar el estado de la orden a Calculada.
Una vez guardado el cálculo oficial, no se deben permitir cambios en:
● Datos generales críticos de la orden.
● Productos de la orden.
● Gastos de la orden.
● Resultado del cálculo.
Esto garantiza que el cálculo histórico no cambie si luego se modifican productos,
categorías arancelarias, tasas de cambio o configuración de impuestos.
Reglas adicionales del módulo
● No se debe calcular una orden cerrada o cancelada.
● No se debe permitir guardar más de un cálculo oficial para la misma orden.
● El cálculo debe hacerse siempre en moneda local.
● Si la moneda de la orden es local, la tasa de cambio usada será 1.
● Si la moneda de un gasto es local, la tasa de cambio usada será 1.
● Si la moneda de la orden o de un gasto es extranjera, debe existir tasa válida
hacia la moneda local.
● La tasa de cambio de la orden se busca usando la fecha de la orden.
● La tasa de cambio de cada gasto se busca usando la fecha del gasto.
● Los porcentajes se capturan como valores entre 0 y 100.
● En cálculos, todos los porcentajes deben dividirse entre 100.
● El margen deseado debe ser mayor o igual que 0 y menor que 100.
● Flete internacional y seguro internacional forman parte del CIF.
● Los demás gastos se consideran gastos locales asignados.
● El resultado oficial debe guardar copia de los valores usados en el cálculo.
● El módulo debe usar el mismo layout general de la aplicación.
Confirmación y cierre de orden
Una orden de importación en estado Calculada puede ser cerrada cuando el usuario
confirme que el cálculo oficial de landed cost ya fue revisado y aceptado.
El cierre de una orden representa la finalización del proceso de importación dentro
del sistema. Una vez cerrada, la orden queda bloqueada para modificaciones y solo
podrá ser consultada.
Cerrar orden
Desde el detalle de una orden o desde la pantalla del resultado oficial del landed
cost, el sistema debe mostrar un botón con el texto Cerrar orden, únicamente
cuando la orden esté en estado Calculada.
Al presionar el botón Cerrar orden, el sistema debe mostrar una pantalla de
confirmación con el siguiente mensaje:
“¿Está seguro que desea cerrar esta orden de importación? Una vez
cerrada, no podrá modificar sus datos, productos, gastos ni resultado de
cálculo.”
Debajo del mensaje debe haber dos botones:
● Cancelar
● Aceptar
Si el usuario pulsa Cancelar, el sistema debe regresar al detalle de la orden sin
cambiar el estado.
Si el usuario pulsa Aceptar, el sistema debe intentar cerrar la orden.
Validaciones para cerrar orden
Antes de cerrar una orden, el sistema debe validar lo siguiente:
● La orden debe existir.
● La orden debe estar en estado Calculada.
● La orden no debe estar cancelada.
● La orden debe tener al menos un cálculo oficial de landed cost guardado.
● La orden debe tener productos registrados.
● El cálculo oficial debe tener costo total de importación mayor que 0.
Si alguna validación falla, la orden no debe cerrarse y el sistema debe mostrar un
mensaje indicando el problema.
Ejemplo:
“No se puede cerrar esta orden porque no tiene un cálculo oficial de
landed cost guardado.”
Efecto del cierre
Al cerrar la orden, el sistema debe cambiar su estado a Cerrada.
Una orden cerrada no podrá ser editada.
No se podrán modificar:
● Datos generales de la orden.
● Productos de la orden.
● Gastos de importación.
● Tasa de cambio usada en el cálculo oficial.
● Configuración de impuestos usada en el cálculo oficial.
● Categorías arancelarias usadas en el cálculo oficial.
● Resultado general del cálculo oficial.
● Detalle por producto del cálculo oficial.
Una orden cerrada solo podrá ser consultada.
Reglas adicionales del cierre
● Solo se pueden cerrar órdenes en estado Calculada.
● No se puede cerrar una orden en estado Abierta.
● No se puede cerrar una orden en estado Cancelada.
● No se puede cerrar una orden que no tenga cálculo oficial.
● Cerrar una orden no debe ejecutar nuevamente el cálculo de landed cost.
● Cerrar una orden no debe modificar los valores calculados.
● Una orden cerrada no debe poder volver a estado Abierta.
● Una orden cerrada no debe poder volver a estado Calculada.
● Una orden cerrada no debe poder cancelarse.
● El cierre debe preservar la trazabilidad histórica del cálculo oficial.
Consulta de orden cerrada
Una orden cerrada debe poder consultarse desde el listado y desde el detalle de
órdenes.
Al consultar una orden cerrada, el sistema debe mostrar:
● Datos generales de la orden.
● Productos registrados en la orden.
● Gastos registrados en la orden.
● Resultado oficial del landed cost.
● Detalle del cálculo por producto.
● Fecha del cálculo oficial.
● Fecha de cierre de la orden, si se decide guardar este campo.
No deben mostrarse botones para:
● Editar orden.
● Agregar producto.
● Editar producto.
● Eliminar producto.
● Registrar gasto.
● Editar gasto.
● Eliminar gasto.
● Calcular nuevamente.
● Eliminar orden.

Nota sobre redondeo
El sistema debe manejar los cálculos con precisión decimal y redondear los valores

Reglas de negocio
● El sistema debe validar que una orden tenga todos los datos necesarios
antes de calcular el landed cost.
● No se debe permitir calcular landed cost si no existe una moneda local activa
configurada en el mantenimiento de monedas.
● No se debe permitir calcular landed cost si no existe una configuración de
impuestos activa.
● No se debe permitir calcular landed cost si la orden no tiene productos
agregados.
● No se debe permitir calcular landed cost si la orden no tiene registrado un
gasto de tipo Flete internacional.
● No se debe permitir calcular landed cost si la orden no tiene registrado un
gasto de tipo Seguro internacional.
● No se debe permitir calcular landed cost si la moneda de la orden es
diferente a la moneda local y no existe una tasa de cambio activa válida hacia
la moneda local.
● Si la moneda de la orden es igual a la moneda local, no se requiere tasa de
cambio y el sistema debe usar tasa de cambio igual a 1.
● No se debe permitir calcular landed cost si un gasto está registrado en una
moneda diferente a la moneda local y no existe una tasa de cambio activa
válida hacia la moneda local.
● Si la moneda del gasto es igual a la moneda local, no se requiere tasa de
cambio y el sistema debe usar tasa de cambio igual a 1.
● Para convertir el FOB de una orden en moneda extranjera, el sistema debe
usar la tasa activa más reciente cuya fecha de vigencia sea menor o igual a la
fecha de la orden.
● Para convertir un gasto en moneda extranjera, el sistema debe usar la tasa
activa más reciente cuya fecha de vigencia sea menor o igual a la fecha del
gasto.
● No se debe permitir dividir gastos por peso si algún producto de la orden no
tiene peso configurado o si el peso total de la orden es 0.
● No se debe permitir dividir gastos por volumen si algún producto de la orden
no tiene largo, ancho y alto configurados o si el volumen total de la orden es
0.
● No se debe permitir dividir gastos por cantidad si la cantidad total de la
orden es 0.
● No se debe permitir dividir gastos por valor FOB si el FOB total de la orden
es 0.
● Los porcentajes deben capturarse como valores visibles entre 0 y 100.
● Ejemplo: si el usuario registra 18, el sistema debe interpretarlo como 18%.
● Para realizar cálculos con porcentajes, el sistema debe dividir el valor entre
100.
● Ejemplo: 18% debe calcularse como 18 / 100.
● El margen de ganancia deseado debe ser mayor o igual que 0 y menor que
100.
● No se debe permitir margen de ganancia igual o mayor que 100, porque
provocaría una división inválida al calcular el precio de venta sugerido.
● El precio FOB unitario no debe registrarse en el mantenimiento general de
productos.
● El precio FOB unitario debe registrarse en el detalle de productos de la
orden, porque puede variar según orden, proveedor, fecha, moneda o
negociación.
● No se debe permitir editar órdenes en estado Cerrada o Cancelada.
● No se debe permitir agregar, editar o eliminar productos de una orden en
estado Calculada, Cerrada o Cancelada.
● No se debe permitir agregar, editar o eliminar gastos de una orden en estado
Calculada, Cerrada o Cancelada.
● No se debe permitir eliminar una orden que ya tenga un cálculo oficial de
landed cost guardado.
● Una orden con cálculo oficial guardado debe quedar en estado Calculada.
● Una orden en estado Calculada puede ser cerrada.
● Una orden en estado Cerrada solo podrá ser consultada.
● El cálculo oficial del landed cost debe guardar los valores utilizados en el
cálculo para mantener trazabilidad histórica.
● El resultado oficial debe guardar la moneda local utilizada, la tasa de cambio
usada, los porcentajes de impuestos aplicados, los aranceles aplicados, los
gastos asignados y los totales calculados.
● Cambiar posteriormente una tasa de cambio, categoría arancelaria,
configuración de impuestos, producto o gasto no debe modificar cálculos
oficiales anteriores.
● No se debe permitir eliminar registros maestros que estén siendo utilizados
por otros módulos del sistema.
● Si un registro maestro ya está siendo utilizado, la alternativa recomendada
debe ser cambiar su estado a inactivo.
● Los registros inactivos no deben aparecer en formularios de creación de
nuevos registros.
● Los registros inactivos sí deben mostrarse en registros históricos donde ya
fueron utilizados.
Requerimientos técnicos
● La aplicación debe ser desarrollada en ASP.NET Core MVC usando .NET 9.
● Se debe utilizar Entity Framework Core Code First para la persistencia de
datos.
● El proyecto debe tener una capa para la aplicación web, una capa para la
lógica de negocio y una capa para la base de datos.
● Se deben utilizar ViewModels para los formularios y validaciones.
● Se deben utilizar DTOs para transferir información desde los servicios.
● La lógica de negocio no debe estar en los controladores.
● La lógica de cálculo del landed cost no debe estar en los controladores.
● Los cálculos deben estar centralizados en servicios de aplicación.
● El sistema debe utilizar servicios para manejar las operaciones principales de
los módulos, como órdenes de importación, productos de la orden, gastos de
importación, tasas de cambio y cálculo de landed cost.
● La aplicación debe utilizar migraciones de Entity Framework Core para crear y
actualizar la base de datos.
● Las entidades deben manejar correctamente sus relaciones mediante claves
primarias y claves foráneas.
● Los formularios deben validar la información usando ViewModels y
validaciones del lado del servidor.
● Las validaciones críticas deben realizarse del lado del servidor, aunque
también se pueden agregar validaciones del lado del cliente.
● Para valores monetarios, porcentajes y cálculos financieros, se debe utilizar el
tipo de dato decimal.
● No se debe usar double o float para cálculos monetarios.
● Los valores monetarios deben mostrarse en pantalla con 2 decimales.
● Los cálculos internos deben realizarse con la mayor precisión posible y
redondearse preferiblemente al mostrar el resultado final.
● Todas las pantallas deben usar el mismo layout general de la aplicación.
● El menú principal debe estar disponible en todas las pantallas.
● El sistema debe ser visualmente entendible usando Bootstrap u otro
framework CSS similar.
